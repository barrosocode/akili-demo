# Relatório — Spec 02 (frequência do aluno)

**Data:** 2026-09-11  
**Repo:** `akili-site`

## Resumo

O dashboard do aluno ganha cards de frequência (disponíveis / vistas / pendentes / % vistas) **além** dos KPIs de progresso legado. A lista de materiais mostra um resumo em uma linha. Supervisão read-only não consome o endpoint.

## Envelope

Laravel responde com chave `frequency` (não `{data}`). `studentLaravelRequest` não unwrapa essa chave; o BFF usa `unwrapResource(payload, "frequency")` e devolve `{ data }` via `jsonSuccess`.

`unwrapData` das rotas antigas (dashboard, materials, progress) **não** mudou.

## Arquivos

- `lib/api/envelope.ts` — `unwrapResource`
- `app/api/student/kpis/frequency/route.ts` → `GET /mobile/student/kpis/frequency`
- `features/student/hooks/use-student-frequency.ts`
- `features/student/components/student-dashboard-view.tsx`
- `features/student/components/student-materials-list.tsx`

## UI

- Empty `available_count = 0`: “Não há aulas disponíveis na sua matrícula.”
- Sem gráfico de acerto no aluno.

## QA manual

1. Network: browser `GET /api/student/kpis/frequency` recebe `{ data: { available_count, viewed_count, pending_count, viewed_percent } }`.
2. BFF encaminha `GET /mobile/student/kpis/frequency`.
3. Números batem com o catálogo (disponíveis = materiais; vistas = `status != not_started`).
4. Cards de progresso geral / tempo estudado continuam visíveis.
5. `/aluno/supervisao/...`: sem request de frequência.
