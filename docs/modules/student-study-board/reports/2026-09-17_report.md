## Resumo

Casca do quadro de estudos do aluno autenticado. GET no BFF lê as chaves `board` e `study_plan` do envelope Laravel (não `{data}`). A tela `/aluno/estudos` mostra o nome do quadro e, sem plano `applied`, um empty state de espera. Colunas do Kanban ficam para `student-study-kanban`. Sem writes.

## Passos manuais de ambiente

- API `akili-api` no ar, com specs 01–04 já migradas.
- Aluno com board (cadastro via `CreateStudent` ou `php artisan study-planner:backfill-student-boards`).
- Sessão mobile Sanctum no portal aluno (`/aluno/entrar`).
- Sem seeder novo no site. Sem migration neste repo.

## Páginas e BFF

| Superfície | Destino |
|---|---|
| Página | `/aluno/estudos` (`app/(aluno)/aluno/(estudante)/estudos/page.tsx`) |
| Nav | item **Estudos** só na sessão de aluno (`lib/auth/portal-paths.ts`) |
| BFF | `GET /api/student/board` → `GET /api/v1/mobile/student/board` (`board`) |
| BFF | `GET /api/student/study-plans/current` → `GET /api/v1/mobile/student/study-plans/current` (`study_plan`, pode ser `null`) |

Browser continua recebendo `{ data }` do BFF (`jsonSuccess`). O Laravel **não** é unwrapado cego: `studentLaravelResource` / `studentLaravelResourceNullable`.

## Exemplos

### GET `/api/student/board` (BFF → browser)

```json
{
  "data": {
    "uuid": "...",
    "name": "Estudos de Ana",
    "status": "active",
    "student_uuid": "...",
    "school_uuid": "...",
    "members": [{ "user_uuid": "...", "name": "Ana", "member_role": "owner" }],
    "current_study_plan": null,
    "created_at": "2026-09-17T14:00:00+00:00",
    "updated_at": "2026-09-17T14:00:00+00:00"
  }
}
```

UI **não** renderiza uuid, e-mail nem DPS. Empty: “Seu responsável ainda não gerou o plano de estudos.”

Com plano `applied`, chips de início/prazo (calendário `America/Fortaleza`) e contagem de avisos. Atalho real: materiais. Sem colunas.

### GET `/api/student/study-plans/current`

Laravel: chave `study_plan` ou `null`. BFF: `{ "data": null }` ou o objeto do plano. A tela desta spec usa o embed `board.current_study_plan`; o GET current fica pronto para o Kanban.

## Conformidade LGPD

| Campo | Classificação | Proteção |
|---|---|---|
| `board.name`, `members[].name` | DP | Exibido só no quadro do próprio aluno; sem e-mail |
| `student_uuid`, `user_uuid` | identificador interno | Tipo interno; **nunca** na UI |
| `tdah_adjustment`, `on_medication` | DPS | **Ausentes** dos tipos e desta tela |
| Storage | — | Sem `localStorage` / `sessionStorage` |

Soft-delete e criptografia DPS são da API. Este módulo só lê.

Logs de BFF não dumpam o envelope completo.
