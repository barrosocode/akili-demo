## Resumo

O player deixa de montar abas a partir das questões. A UI usa `session.visible_tabs`. GET `sessions/current` encaminha `study_task_uuid` e `session_kind`; se não houver sessão (404/`null`), o BFF do browser faz POST. Revisão não marca o conteúdo como concluído. Guardian `readOnly` não dispara writes e vê só as abas da aula (`treino`+`conf`). `desafio` não entra. Sem migration.

## Passos manuais de ambiente

- API `akili-api` no ar, com as specs de sessão por card (`session_kind` + `visible_tabs`).
- Aluno autenticado (`/aluno/entrar`). Abrir material pela lista (aula) e pelo Kanban (`?studyTask=`).
- Sem seeder novo no site. Sem migration neste repo.

Sessões antigas no banco ainda podem ter `visible_tabs` com seis abas. O front obedece o payload; a UI só muda quando a API devolve o recorte certo.

## Exemplos

### GET current (BFF → Laravel)

`GET /api/student/contents/{uuid}/sessions/current?study_task_uuid=...&session_kind=review_r1`

### POST sessão (BFF → browser)

```json
{
  "data": {
    "uuid": "...",
    "status": "started",
    "session_kind": "new_content",
    "visible_tabs": ["treino", "conf"],
    "study_task_uuid": null,
    "shuffle_seed": 42,
    "attempts": [],
    "responses": []
  }
}
```

Lista de materiais: body sem `study_task_uuid`. Kanban: body com uuid do card. Reload da revisão usa a mesma query no GET current.

UI **não** renderiza uuid. Empty de `visible_tabs`: “Esta etapa de estudo não está disponível no momento.”

## Conformidade LGPD

| Campo | Classificação | Proteção |
|---|---|---|
| `session_kind`, `visible_tabs`, `shuffle_seed` | pedagógico / nenhum | Exibidos só como etapas humanas (Conteúdo, Conferência, Revisão) |
| `uuid`, `study_task_uuid` | identificador interno | Navegação/query; **nunca** rotulados na UI |
| DPS | — | Ausentes deste recorte |
| Storage | — | Sem `localStorage` / `sessionStorage` |

`learning_sessions.deleted_at` já existe na API. Logs de BFF não dumpam o envelope completo.
